# 全局语音控制与会话协作边界

## 主人控制同一语音前台

鱼应在同一个 DSH 宿主内保留一个当前语音入口。切换工作会话只改变界面操作的来源，不转移麦克风、不改变当前语音根 ID 或授权 epoch，也不重选模型、复制历史或启动新后台工作者。已开启时再次点击开启返回当前状态；主人可以从其他工作窗口关闭语音、切换听取方式及查看同一份最近对话。

界面控制先由 DSH 的 owner principal 或原生命令入口验证，再进入专用人工路径。代理工具继续使用原有会话权限，不会因主人能从任意窗口操作而获得麦克风、朗读或其他会话历史权限。手工操作仍会使旧代理计划失效。最初开启语音的工作会话已经卸载时，主人仍可从另一存活窗口关麦；授权页撤销授权不依赖任何工作会话存活。

`ownerSessionId` 目前保留为授权来源和已有持久记录的标识，不再用于判断哪个主人窗口可以控制当前语音。选中可见的语音根本身再关闭时，根的预期销毁不会被误报为操作失败。来源被另一个同 ID 的 Agent 替换仍会拒绝。配置保存、音频清理或权限写入结果不明时继续失败关闭，不因切换窗口重试。

## 当前仍有的限制

全局人工控制不等于跨所有 DSH 会话的代理调度已经完成。当前 `voice_message` 仍只连接语音根、发起会话、其后台工作者以及配置中明确列出的 `voiceSession.allowedSessionIds`；跨树接收方必须已经常驻。`voice_control` 只控制该语音根实际拥有的工作者。代理不会因看见一个会话 ID 就自动恢复、停止或读取该会话。

关闭后从另一个工作会话重新开启，或显式新建/接续语音聊天，仍使用现有来源绑定和持久目录规则；本次没有迁移旧身份记录，也没有实现无工作会话时首次开启。不同 DSH 宿主进程之间没有新增全局协调协议。

## DSH API 核查与后续最小方案

以下 API 行为核查基于 DSH 源码 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`。发布版需要继续按实际宿主能力检测，不能把源码 API 的存在当成所有安装版本都具备。

- `subagents.sendMessage`、`list_agents` 和 `send_message` 仅覆盖同一子代理树。它们可以冷恢复本树中可继续的工作者，但不能跨独立会话树。
- `sessionQuery.listSessions` 和 `readSession` 可读取逻辑会话目录及日志，不会自动运行代理。模型侧 `session_search` 等查询工具另有工作目录范围校验，不是全局搜索工具。
- `agents.list/get` 只反映常驻 Agent。`sessionController.resolveAgent` 可恢复普通会话，并拒绝把子代理当成普通会话恢复。它是宿主 API，不是面向模型的授权检查。
- `sessionController.prompt` 会把输入标记为用户消息。代理间转达不能借用它冒充用户指令。现有 `voice_message` 跨树路径使用带来源的 notice；这个区别必须保留。

要让语音或视觉前台与主人全部可访问的会话协作，需要独立的宿主会话桥接层：按已验证的主人范围提供分页目录；区分常驻、冷普通会话、可继续子代理、归档、外部及不可恢复会话；在发送时再次检查目标、权限和归档状态；保留模型转达来源、原始用户证据与消息回执；对未支持的恢复路径明确报障。不能通过放宽麦克风的 `allowed` 判断、绕过原生子树归属，或把 notice 改成 user 消息来实现。

鲸曈等前台也应共用这些边界：前台生命周期属于宿主，当前窗口只是观察/交互来源；麦克风或视觉采集授权、跨会话消息权限、任务控制权限分别管理。人工停止与配置优先，切换窗口不是新任务或新权限。

## 回归覆盖

新增覆盖同一根的跨窗口显示、重复开启幂等、epoch 不变、跨窗口切模式、原来源销毁后关闭/撤权、可见语音根关闭回执、同 ID 替换拒绝，以及普通代理不能使用人工路径。真实 Typert Gateway 测试覆盖 owner 跨窗口对话流与非 owner 拒绝。合成音频帮工测试不等于本机麦克风、听感或设备切换验收。
