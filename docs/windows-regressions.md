# Windows 离线回归修复（0.5.10）

本版保留 0.5.9 的单一面板交互，处理 [issue #6](https://github.com/Emikosama/dsh-whale-ear/issues/6) 中的 Windows 本地回归报告。不会启动麦克风、朗读私人文本或下载真实模型。

## 已确认的修复

- Edge 帮工测试只在 POSIX 平台检查 `0600` 权限位。Windows 的 `stat` 权限位不能用来验证 POSIX 权限或 Windows ACL，不能据此断言音频泄露。音频字节、现有文件不覆盖、非法请求不写入及错误不泄露原文等测试继续在 Windows 执行。生产帮工的排他创建逻辑未改。
- 测试驱动明确使用 UTF-8 向帮工发送 JSON，并覆盖系统默认 CP1252 时的中文文本和中文路径。生产调用方和帮工原本已明确使用 UTF-8，不依赖修改系统语言或全局环境变量。
- 下载器在打开模型文件后，首次保存任务进度如果失败，原先会绕过文件关闭逻辑。现在首次进度保存也在文件句柄的 `try/finally` 内，异常时先关文件，用户才能明确恢复任务。没有新增盲目重试、复制替代重命名、放宽哈希或自动重新下载。

## 哈希失败恢复的证据边界

报告对应的测试先收到同样长度的错误下载，再由用户显式恢复并取得正确字节，并不是覆盖已经安装的模型。Linux 修前可通过，但 [Windows Node 24.15.0 / Python 3.11.9 实测](https://github.com/Emikosama/dsh-whale-ear/actions/runs/43106160415/job/130809917608) 已在普通恢复与重启恢复两条路径复现 `EINVAL: invalid argument, open`，错误发生在重置完整坏文件时，不在目录重命名时。

该分支原先使用 `O_WRONLY | O_TRUNC`、不带 `O_CREAT` 打开文件。[Node v24.15.0 内置 libuv 的 Windows 实现](https://github.com/nodejs/node/blob/v24.15.0/deps/uv/src/win/fs.c) 将其映射为 `TRUNCATE_EXISTING`；本次 Windows 环境拒绝了这个打开操作。现改为只打开已有文件，核对句柄与路径仍是同一个独立普通文件，再对句柄执行 `truncate(0)` 并在 `finally` 关闭。没有新增创建、删除或覆盖目录的回退，也没有放松来源、大小与 SHA-256 校验。确定性测试在旧实现返回 `EINVAL`，新实现通过；另有身份变化和截断失败时不下载、不截断错误目标且关闭句柄的回归。新提交的真实 Windows 通过状态仍以 CI 为准，不能仅以 Linux 注入测试替代。

新增的离线测试分别验证：首次进度保存失败不会漏关文件、目录提交遇到共享冲突后保留已校验文件供显式恢复、哈希失败后重启仍能完整重新下载。原测试还会输出失败的具体错误码和信息，并断言第二次请求不携带旧 Range/If-Range、下载字节正确、安装完成不等于模型已加载。

Windows CI 新增 Node 24.15.0、Python 3.11 的全量离线回归，与报告的运行时版本系列一致；原来的 Windows 最新 Node 24 单包测试继续保留。CI 使用本地 HTTP 假模型和假的 Edge 合成模块，不联系微软，不下载模型权重，不代替真实麦克风、Windows ACL、显卡或本机播放验收。测试结论以对应提交的实际 CI 结果为准。

## 0.5.17：无符号链接权限的安全测试（issue #12）

本机报告为 Windows 10/11 普通用户、Node 24.15.0、未开启开发者模式：518 条 Node 测试中三条在构造文件符号链接时返回 `EPERM`，产品安全检查尚未执行。无需为了测试修改系统权限或以管理员身份运行。

测试现在在攻击夹具所在文件系统中创建、验证并删除一个临时文件符号链接。只有创建链接这一步的已知能力错误（`EPERM`、`EACCES`、`ENOSYS`、`ENOTSUP`、`EOPNOTSUPP`）会明确标为 skip；其他错误、夹具创建后的失败及产品安全断言仍然失败。有能力的 Windows 和 Linux 环境继续执行原安全检查，不按 Windows 平台一律跳过。

- 三个需要真实链接的用例分别覆盖下载意图记录、运行时解压输出、本地 TTS 模型文件。跳过不代表相应防护在本机已经验收。
- 缺失文件、错误大小和未知模型独立测试，不能随链接用例一起跳过。TAR/ZIP 中的链接条目、非法路径、大小和哈希检查继续执行。
- 链接目标采用格式有效的意图记录及同目录、同大小的模型文件，避免因为无效内容而误判链接防护有效。
- 测试专用子进程同时模拟同步和异步 `symlink` 拒绝，验证仅这三个用例因能力限制跳过，其他安全检查通过。这个模拟不是 Windows 本机验收。
- Linux CI 设定 `WHALE_TEST_REQUIRE_SYMLINK=1`，缺失能力时必须失败，确保至少一条 CI 路径执行真实文件系统链接防护。普通本机测试不必设置它。

本次仅修改测试和说明，不更改产品防护、许可、朗读选择或系统设置。`enable` 等待完整重启的升级状态与当前 `tts.provider = off` 是独立事项；保留原本机验收记录，不将它们算作已修复或已复测。

## 0.5.20：朗读检查的停止与中文返回值

- 朗读准备同时检查 Windows 播放组件与 Edge 依赖。取消时必须等待两个检查进程都结束；一个先退出不能代表整个准备工作已停止。任一进程未能确认退出，都返回未确认并阻止后续播放，不会换供应商继续尝试。
- 子进程 JSON 按连续 UTF-8 字节流解码。中文音色标识或表情跨越管道数据块时不再变成乱码，原有返回数据大小上限继续按原始字节执行。
- 旧语音根占用产生的 `blocked` 请求可正常显示在 Agent 请求页。读取状态和重复确认不会自动重放开麦，也不会将已知的占用问题误标为未知结果。权限与完整重启后的恢复条件不变。

离线回归覆盖两个检查进程的不同退出顺序、迟到退出、无法确认退出、正常与降级检查、中文和表情的全部字节分割点，以及真实控制层结果到界面解码的往返。Windows CI 与浏览器夹具结果以对应提交为准；这些测试不代表真实设备上的麦克风或声音播放验收。

## 0.5.21：朗读中的停止与首次配置切换

- 正常朗读的 `busy` 状态不再误记成结果未知，主页关麦和设置中的停止操作能实际发出。真正未确认停止时，新的播放和配置写入仍被拦截；显式关麦允许执行，只有确认空闲且未阻塞的状态才能解除对应锁。
- 取消或状态回复乱序时，旧成功结果不能覆盖更新的未确认停止；后续明确读取到空闲状态才解除锁。
- 首次配置保存期间离开、卸载或切换来源会话，旧请求不能推进步骤或关闭新页面，成功设置写回仍保留。
- 包版本、运行期版本和当前版本入口统一为 0.5.21。旧版本入口保留作历史记录；同名包升级遵循宿主移除后安装的流程，版本号变化本身不绕过 `already-installed`。

本地验证：Node 587 项、Python 102 项通过；UI 198 项通过，11 项需完整宿主工具链的测试跳过。新导航用例使用真实 React/jsdom，旧代码失败、修复后通过；停止用例使用实际控制器与协议，并覆盖迟到回复。构建、包清单和版本入口一致性通过。完整宿主与 Chromium CI 以最终提交结果为准，本轮未执行 Windows 实机、麦克风、扬声器或听感验收。

## 0.5.22：Melo 输入管道的中文与表情

Melo 工作进程原先对每个输入数据块单独解码 UTF-8。一个中文、重音字符或表情跨块时会被替换，导致实际合成文字变化；模型、运行组件或输出路径里的多字节字符也可能损坏。现使用连续流解码，并在结束时刷新残余字节。请求上限仍为 65,536 个原始字节，超限在加载原生模块前拒绝，不再反复扫描已解码字符串估算字节数。

9 项隔离进程回归运行生产 worker，固定字节边界，验证完整块对照、分块文字、三类中文路径、精确大小边界及脱敏错误。旧实现同组测试 5 失败、4 通过；新实现 9 项通过。相关 TTS 回归共 45 项通过，全量 Node 596 项与 Python 102 项通过。模型文件使用稀疏尺寸夹具，原生合成用替身，不代表 Melo 听感或 Windows 音频实机验收。Qwen、系统语音、网络传输和模型校验权限未变。

## 0.5.23：运行组件检查的退出确认与 Qwen 完成信息

- 本地模型的运行组件检查与朗读共用受控子进程执行器。取消或超时后等待实际退出，必要时终止进程；无法确认退出时保留未知结果，不将它改成普通安装失败或已停止。
- 静态版本/import 检查有界读取两路输出，按原始字节限制总量，错误不带回原始日志。模型、归档与运行组件的固定来源、大小和 SHA-256 检查不变。
- Qwen 完成计数在整个当前管道数据块内提取后，才保留有限尾部处理跨块信息。上游 b12110 在完成行后还输出耗时和输出路径，较长尾部与完成行合并时不再丢失计数。缺少完整标记、异常退出、截断生成和无效音频仍拒绝播放。

离线回归包含确定性管道分块和合并、完成标记的全部分割点及长尾部、不完整标记，以及取消期间进程退出确认。回归使用合成夹具，不代表真实 Qwen 合成、麦克风或 Windows 听感验收。各平台结果以对应提交 CI 为准。

## 0.5.24：计算依赖检查的取消、超时与关闭

- ASR 安装前的计算依赖检查和独立检查改为共用受控进程执行器。12 秒超时预算与 32768 原始字节输出限制保留；取消、超时、超量输出先确认进程退出，不把仍存活的检查进程标成已暂停或已取消。
- 关闭安装器会中止并等待所有独立与安装内检查。确认退出后才释放目录锁；无法确认时保留锁，禁止重复检测或恢复受影响任务，但仍可读取已有状态与安装计划。
- 并发检查在启动、返回与发布能力前复查取消和隔离状态。较晚的成功结果不能覆盖较新的未知结果，也不能据此继续下载。关闭后不能启动新的检查。
- 正常缺依赖仍返回原有说明；取消和未知结果不再伪装成缺依赖。原始 Python 输出不写入错误，不自动装包、下载权重或切换计算后端。

新增回归用实际 bundled Python 检查入口和临时模拟依赖，覆盖忽略 SIGTERM 的进程、真实 12 秒超时、超量多字节输出、重复关闭/取消、并发晚成功及未知结果保锁。POSIX 原生进程用例在 Windows 明确跳过，跨平台逻辑测试继续执行；这些夹具不是实际 GPU、麦克风或听感验收。

## 0.5.26：录音设备失败与恢复

设备创建、启动或录音过程异常会终结对应请求并尝试关闭本次流，不再留下阻止后续侧键/键盘录音的占用。录音构造失败不会取消原有录音；统一收尾按身份清理，旧任务不会释放新任务或迟到恢复常听。

启动准备与常听恢复按次序执行，显式停止不等待启动次序锁。慢设备切换期间收到停止、看门狗超时或原授权/轮次已改变时，不继续开流；撤权后的收尾不重新开启常听。失败不自动重试，PTT 仍需先松键再按。

本轮离线故障注入覆盖设备构造/start/run、请求归属、同步线程启动失败、旧任务晚失败，以及停止/撤权/迟到暂停竞争。驱动 close 抛错时保留“关闭未确认”诊断，不把异常吞掉后宣称硬件已停止。Windows 真机的占用设备、拔插、麦克风权限拒绝与恢复仍需另行验收。

## 0.5.27：独立朗读检测的取消与卸载

从设置或工具单独启动的本机语音检测也纳入 TTS 运行占用，与朗读和候选本地模型验证互斥。朗读内部仍可执行所需检查，但不会重复申请自身占用。停止、撤权和卸载会取消并等待检测，无法确认退出时保留阻断；迟到结果不提交为新检测成功，也不清除退出未确认状态。

固定能力查询、正常缺少依赖时的说明与既有播放权限不变。检测忙碌不会排队启动试听，不自动重试或切换服务。本轮回归使用真实插件接线与受控子进程，不代表 Windows 设备播放或驱动退出的实机验收。

## 0.5.28：取消识别中的 PTT 与无关朗读检查

PTT 自动收音结束后仍可能处于识别阶段。此时 Escape、焦点变化或钩子停止按具体录音对象取消，迟到文字与错误不再提交；已结束收音的输入轮次也会发送取消信号，清理处理中状态与尚未播放的结束提示音。旧轮次取消不释放新录音，不强制终止 Python 推理线程，也不声称底层计算已经停止。

普通系统语音和本地语音的播放前检查只查询所需能力，不再启动无关的 Edge Python 检查。Edge 朗读仍检查依赖，公开「检测」仍查询完整能力；本地模型与运行组件的固定来源、大小、哈希校验和合成前检查保持不变，不增加缓存或自动重试。

受控复现使用真实运行时、Windows 适配器和进程执行器，仅子进程使用替身：旧实现中，无关 Python 检查挂起会让系统/本地朗读等待约 8 秒，拒绝退出则约 9.5 秒后阻断。该结果说明检查依赖的额外等待，不代表真实 Windows 听感或端到端提速。新版本的实机麦克风、扬声器与设备退出验收仍需单独进行。

## 0.5.29：语音帮工启动与安装恢复

帮工启动超时、协议不兼容或命令管道故障统一进入退出确认。旧进程真正退出前不启动替代进程，迟到的 ready、录音与状态消息不再生效。停止/卸载也覆盖尚未就绪的启动请求；无法确认退出时保留暂停状态，热升级不能绕过。脚本路径或同步启动失败修正后可以重新发起，不再永久复用一次已失败的启动 Promise。

已安装任务重启时发现缺失或变短文件，显式恢复会继续使用固定清单内仍校验正确的文件，补齐缺失/损坏部分，恢复原任务路径；不自动应用模型、不改写语音授权。用户复用的外部模型源仅复验，不移动或删除。取消与恢复相互排斥，已完成原子提交的安装不能再被标记成已取消。

回归使用真实插件/安装器入口、受控进程事件及临时文件。云端 Windows CI 的控制流程通过不替代真实设备、驱动、模型加载时间或听感验收；已发送终止信号也不等于已确认进程退出。

## 0.5.30：本地朗读前的重复校验

内建托管模型的普通朗读不再先做一次诊断式本地模型检查。每段实际合成仍通过安装器完整验证模型、运行归档与展开文件的大小和 SHA-256，并检查运行组件版本；未引入哈希缓存或跨次复用校验结果。公开检测、显式合成验证、注入适配器和缺少托管解析器的行为保持不变，不伪造 localReady 或 synthesisVerified。

完整异步校验返回后，再检查请求是否已取消及配置是否改变，防止旧设置继续启动合成。这补齐校验等待期间的配置窗口，不承诺合成启动后任意设置变化都会立即停止，也不声称消除了文件校验与原生进程打开文件之间既有的 TOCTOU 边界。

真实生产构造的 A/B 使用同一 128 MiB 合成模型安装目录与小型 Node 替身进程，交替测量顺序，没有注入 localAdapter。短句完整校验/版本进程从 2 次变 1 次，三段从 4 次变 3 次，每次少读 134,218,850 个逻辑字节；公开检测仍为 1 次完整校验。短句各 6 次测量中位 325.6→181.7 ms，三段各 4 次为 744.0→582.1 ms。数字仅代表云 Linux 暖文件缓存夹具，不是物理磁盘流量、真实推理或 Windows 首音提速。

回归覆盖同尺寸篡改并还原时间戳、分段之间篡改、校验中取消/卸载、版本进程退出未知、配置改变以及完整公开检测。Windows CI 使用受控进程契约验证，本地 Linux 另运行真实小型替身进程；真实模型、Windows 设备和声音仍未验收。

## 0.5.31：实时识别积压与输入故障反馈

PTT 连续松按遇到慢 ASR 时，旧版每段都会并行进入识别，最终却只能投递最新一段。实时输入现共用有界闸门：一项运行、一项最新等待；新录音开始即撤销旧等待项，原生计算不被硬杀，返回后丢弃过期结果并跳过后续声纹/韵律。常听暂停或停止撤回自己的等待项，原有 20 秒音频缓冲上限不变。显式文件转写、韵律分析和注册不纳入本次闸门，不能据此宣称整个帮工推理已串行。

生产录音/PTT链与替代设备、阻塞模型复现中，连续八次有效输入在旧版启动八次模型计算；修复后仅第一和第八次进入计算，仍只投递最新一句。回归另覆盖新一轮尚未松键即释放旧等待、撤权、代际变更、取消不释放正在运行项、常听/PTT交接及异常收尾；它们不是实际模型 CPU/内存或 Windows 驱动测量。

输入故障沿既有私有状态流投影白名单代码，不显示原始异常、路径或识别片段。主面板复用原有状态与提示区域，故障时保留关麦和设置入口；旧轮次或授权不匹配的错误被拒绝，按键开始、刷新或设备枚举不代表恢复，当前成功转写及撤权/换根才清除此状态。Python帮工身份事件与Node模拟帮工至React的订阅更新分别验证；新增Chromium场景核对三类提示在不同窗口尺寸下完整可见。

本轮不解决已发现的旧设备流关闭与下一流启动交接问题，也未做最新版本的真实设备、连续语音听感或端到端首音验收。前一版用户现场记录保留在 local-acceptance-2026-11-11.md，不将其作为本次新改动的验收。

## 0.5.32：录音流关闭与下一次启动

物理麦克风占用与输入轮次分离，覆盖设备构造、启动、采集及关闭。PTT、注册录音、自由麦和唤醒模式共用占用；显式文件分析与实时推理闸门不变。只有 close 成功才释放；stop 抛错仍尝试 close，close 抛错保留流引用并阻止后续打开，不能把逻辑停止当成设备释放。帮工状态新增 captureDevice 四态 released、owned、closing、close-unconfirmed。

下一次采集最多在后台等待两秒，等待期间松键、停止、撤权或轮次变化会撤销启动。等待超时提示设备不可用，不自动重试按住的按键。自由麦暂停异步关闭旧流，不阻塞按键队列；每条流只有一次关闭任务，已进入回调的旧流也不能向恢复后的缓存追加音频。关闭失败后，当前有效的自由麦恢复尝试报告一次设备故障并停止重试；旧轮次的清理不向新的输入写错误。

0.5.32 的关闭失败需要完整重启宿主；单纯关麦再开仍会复用被阻断的帮工。0.5.33 补齐这一恢复路径，见下节。

离线生产链测试用有限阻塞的替代设备复现旧版新流构造早于旧流关闭；回归覆盖连续按放、四种 PTT/自由麦交接、构造/start/stop/close 故障、关闭中撤权、迟到回调和退出上界。独立交错审查验证松键与失败判定、自由麦恢复与旧流关闭的竞争。本次未进行 Windows 实际麦克风、独占驱动、设备拔插、声音或模型时延验收。

## 0.5.33：真实释放确认与旧朗读隔离

显式关麦从撤回采集授权起保持清理中状态，覆盖旧会话和朗读退出，再通过不加载模型、不枚举设备的轻量回执核查物理释放。已确认 released 的健康帮工保留，不为普通开关麦重复启动。短时等待仍未释放、关闭失败或回执无效时，等待旧帮工实际退出；下一次明确开麦才创建新帮工。无法确认退出时继续阻断，刷新状态也保留完整重启 DSH 的提示。不自动开麦、修改设备权限、重启驱动、重试采集或恢复旧输入。

真实 Python 帮工与生产 UI/管理器的离线链路验证 close 故障后的关麦/开麦恢复、健康帮工保温、hung close 的进程退出与并发新授权排队；受控进程测试验证退出未知及迟到退出仍不解除阻断。

朗读取消除停止当前原生进程外，还隔离旧模型步骤中尚未派发的朗读及同回合自动续步。原生宿主的 toolSet 身份、pre-step 回合/步骤与实际领取的输入 ID 一起用于判断，不用每个工具可能不同的 AbortSignal 代替步骤身份，也不取消其他工具。主人经宿主文字入口输入、或新的麦克风输入被领取后，即使仍在同一回合也能继续说话；guest、worker 和重复旧消息不能解除打断。显式独立调用与后续新回合保留原授权检查。

固定源码及已发布官方 rc.1 的真实 AgentLoop、NativeExecutor、pipeline、文字入口与 Inbox 均有回归。输入来源由宿主生成，测试验证该生成链，不宣称验证了 Gateway 身份认证；原生音频进程、麦克风与模型仍使用替身，Windows 听感与设备验收另行进行。界面只复用原有提示区域，没有新增面板；短窗可见性由 Chromium 回归检查。

## 0.5.34：语音帮工中断后的状态与恢复

语音授权与音频服务是否可用分别显示。请求管道断开或帮工意外退出时，已有授权仍保留，主面板及时显示录音不可用；未知听取方式不再冒充按住说话。刷新和读取设置只读取缓存，不能重新启动帮工。关麦仍可直接操作，随后明确开麦沿用保存的设置，不需要重新授权。旧帮工清理中或退出未确认时，仍以原有等待或完整重启提示为准。

普通进程故障可在同一有效授权下重启帮工，但不自动恢复自由麦或唤醒采集：新帮工先处于按住说话，界面同步显示实际方式。需要时明确切换方式，或关麦后重新开麦。`voice_status` 的完整设备查询保留原有可启动帮工的行为，与首页只读刷新不同。

快速连续故障采用 1、2、4、8、16 秒退避，最多五次自动重试。收到就绪消息不会立即清空失败次数；同一个已就绪进程持续稳定存活 30 秒后，才恢复重试预算。关麦和卸载会取消待重启及稳定期计时，旧进程消息不能改变新进程的预算。

回归包含真实受控 Python 子进程的请求管道关闭、EOF、SIGKILL、生产界面关麦/开麦，以及可控计时的退避上限和旧进程反例；仅替换音频设备，不读取真实麦克风、不运行识别模型或联网。Windows 设备、驱动、全局热键和真实声学表现仍需单独验收。

## 0.5.35：检测期间停麦与键盘松键竞争

打开朗读设置会自动检查本机组件，旧界面把这个只读检查与所有操作共用同一忙碌锁，导致自由麦仍在采集时无法点击关麦。现在只有显式关麦可抢占朗读或计算依赖检查，其他设置写入仍串行；重复停麦不会叠加，迟到的旧读取也不能覆盖停止结果。TTS 关麦继续等待原后端停止与采集释放回执，不能把客户端请求取消当成进程已退出。无音频的计算检查不延迟麦克风释放，但保留原有有界检测与写入互斥，未确认退出的安全锁不放宽。

切页、返回主页和切换来源只丢弃旧检测的界面结果，不顺带调用全局朗读取消，也不声称后台检测已被杀掉。退出插件时仍按现有生命周期清理。

键盘工作线程的周期检查可能在读取配置期间收到正常松键；旧版随后先看到物理按键已松，误走漏键取消。现在检测到队列内已有边沿时先交回唯一消费者处理，不提前清除按住状态。授权代际、绑定变化和失焦仍优先取消；真正缺失松键事件仍取消。微软 [LowLevelKeyboardProc 契约](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc) 明确钩子在异步键状态更新前调用，本实现先同步入队再返回；钩子丢失或系统访问限制不被当成正常松键。

针对性回归使用生产 controller、界面、命令入口和进程管理器，检查两种读取完成顺序、停止未知、普通写入互斥、导航与迟到结果；键盘回归使用生产事件队列、工作线程和 Recorder，覆盖主键、修饰键、真漏键、上下文撤回、旧识别收尾及键鼠所有权。新的旧识别竞争用有限屏障和线程结束确认控制顺序，不靠固定等待推定完成。实际 Windows 钩子、设备驱动、热插拔和听感仍需实机验收。最终通过情况以对应提交的 CI 为准。

## 0.5.36：按住说话接管与设备列表

PTT 抢占会清除 Python 尚未完成的连续监听采集，但此前已识别并进入 Node 发送队列的结果只检查监听模式代次。一个管道批次内先收到转写、后收到按键开始时，即使面板已显示接管，旧转写仍可能被发送。现在通过会话、采集代次与递增序号验证的 PTT 开始事件，会使尚未发送的自由麦和唤醒结果失效；在原有发送前检查处拦截，不增加协议或操作权限，也不撤回已交给宿主的消息。新 PTT、恢复监听和没有抢占的正常连续输入保持有效。

回归遵循真实宿主同步 steer/followup 契约，用首次语音根初始化的 agents.create 异步边界固定队列，逐条确认帮工事件已被处理后再解除屏障；不依赖管道分块或固定等待。所有音频与输入事件均为受控合成，不代替物理按键或实际声音验收。

设备专用查询最多返回 128 项，完整诊断状态此前只返回前 8 项，随后覆盖同一界面缓存。现在两条查询使用同一上限；状态工具的人类可读摘要仍只展示前 6 项，不增加开流或自动切换设备行为。测试验证两条生产入口的完整候选一致；额外受控 Node→Python 流程检查缺失设备报错、改回系统默认、模式切换及下一次录音读取已保存设备。热插拔、驱动重新枚举与真实输入仍需 Windows 实机验收。

## 0.5.37：自动状态与紧凑控制

回答速度仅在当前会话已完整读取且语音完全停止时显示，明确不支持的档位不再占用按钮。设置页保留兼容策略及当前档位说明；开麦、停止中、未知结果和新会话切换不会留下可误点的档位。主面板常态高度从 304 缩至 256 像素，短窗口继续按可用高度限制，不让主页滚动；字号和交互目标保持可用。

移除只为读取事实的刷新按钮。首次挂载、进入设置、返回窗口和连接恢复时读回配置；缓存读取失败按 0.75 秒至 30 秒退避，面板收起、窗口隐藏或卸载时暂停。对话和模型流意外结束后按会话代次重连，主动取消不重连；没有健康状态的持续轮询，也不因重连增加付费档位探测。设置和授权结果未知时只读回事实，不再次提交原操作。原生音频退出、撤权与安装未知退出仍由各自明确回执约束。

自动读取保留同页未保存表单及其 CAS 版本；发现外部修改时给出“放弃草稿并使用最新设置”的明确选择。保存一个分区不会清空另一个分区草稿。读取缓存期间仍可显式关麦，迟到读取不覆盖较新的停止结果。

麦克风候选列表仍是已发现设备的缓存，本版不为刷新列表开启录音或自行切换设备。硬件及本机语音检测保留原有进程退出保护；实际探测、下载、试听与敏感授权并未变成自动重放。默认模型安装计划准备失败后的重试仍是选定计划操作。所有本地自动化、DOM 和远端浏览器验证均使用受控传输，不代替 Windows 设备与实际声音验收。
