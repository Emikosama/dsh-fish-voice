# Agent 直接修改插件配置

使用 `voice_manage execute` 修改音频设置、本地模型路径、朗读设置、回答速度、对话可见范围、音量、首次配置完成状态和经过安装验证的模型选择。普通配置首次调用就可执行，不需要宿主提问服务，也不因旧人工设置值而再次确认。

`request-owner-change` 保留为配置执行的兼容别名，使用同一组参数与检查，不再弹出问题。`prepare` 仍仅生成预览计划，不执行；需要调用时优先使用 `execute`。

例如先读取设置版本，再调用：

```json
{"action":"execute","operation":"set-performance-mode","params":{"revision":"读取到的版本","performanceMode":"fast"}}
```

## 执行边界

- 配置仍使用严格参数校验、真实调用会话身份及 revision CAS。Agent 不能自行声明人工身份、批准或同意。
- 新的人工操作会使并发计划失效并发送取消信号。读取最新版本后可再次提出配置修改，旧人工值不永久锁定字段。
- 显式撤销总授权或对应普通配置权限仍阻止执行。历史权限记录继续读取，无需迁移；默认空授权记录不等于显式撤权。
- 未知结果会锁住对应操作，先核查实际状态，不自动重试。重启不重放计划。
- 仅保存本地朗读设置或应用已验证的安装结果不会播放声音，因此不要求播放许可。实际试听、开麦、持续监听、会话切换、模型下载与外传文本继续检查各自范围。
- Edge 配置仍要求已有文本传输授权，Agent 不能提供 `edgeTextTransmissionAccepted`；耳机佩戴事实仍须主人确认。敏感信息规则不变。

## 验证范围

纯 Node 回归覆盖直接配置、兼容入口不提问、旧值不阻塞、人工并发修改、显式撤权、未知结果、伪造耳机事实与 Edge 同意。宿主集成测试需固定版本宿主源码；此变更不代表已验证真实桌面、麦克风或第三方服务。
