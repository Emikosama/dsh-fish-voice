# 0.5.11：开麦、对话与设置

本轮对应 issue #7，以 0.5.10 / 03ffb71d 为基础，不覆盖现有工作目录，不变更模型、默认回答速度或现有设备配置。

## 实际交互

- 进入面板、切换操作会话、窗口重新获得焦点、重新展开会读缓存状态。短时间焦点事件合并，不使用定时轮询。自动读取不会开麦、启动 Python、加载模型、下载或提交写操作。
- 第一屏显示麦克风归属、对话、回答速度入口和设置。技术诊断在“设置 → 高级 → 诊断详情”；未读取不写成“已关麦”，已开启也不等于实际正在录音。
- 主按钮只开/关本窗口。麦克风属于别的窗口时，主按钮不可用且解释原因；独立“让这个窗口接管麦克风”显示中断风险，确认后才发送。请求携带用户确认时的所有者，核心串行队列再次校验；中途所有者改变会拒绝，不终止新所有者。
- 设置自动读取；切换会话会清除上一来源的未保存草稿。同一会话的焦点刷新只读状态，保留正在编辑的设置。写入失败保留错误和不确定状态，不被先前排队的刷新掩盖；不会自动重发写操作。
- 设备下拉显示系统默认和候选名称。明确开麦、新建或接续成功后，只向已经运行且声明支持的 helper 读取设备列表，最多 128 项、超时 1.5 秒。这个独立操作只枚举设备，不重载配置、不挂新键盘钩子、不加载模型或建立音频流。失败不撤销已成功的开麦。
- 初始尚无设备观测时保留系统默认与手动输入，并说明列表何时可用。手动“序号”和“名称”明确分开，序号存为数字；包括纯数字名称在内的已有配置原样保留。枚举不代表录音权限、设备仍在线或实际音频已测试。
- 回答速度沿用已有 fast / balanced / high / compatibility 契约，显示“快 / 标准 / 仔细 / 跟随模型”。首页入口显示保存配置，下一次开启生效；不会暗改成“标准”。不支持项、先关麦/正在收尾/状态失效都有短说明。
- 保留用户要求的“桌宠”设置入口，点击显示“计划开发中”，不启动或模拟桌宠功能；未配置声纹的用户不再看到无注册入口的启用开关。已启用声纹仍可关闭，并能在保存前反悔。
- 关闭语音可能结束其后台任务，因此本轮保留明确的关麦步骤，不把“修改快捷键”偷偷转换成关麦。已绑定按键在首页提示，持续聆听说明麦克风常开。

## 参考而非照搬

- [Discord 设备下拉与输入模式](https://support.discord.com/hc/en-us/articles/214925018-Where-d-my-Audio-Input-go-Various-Voice-Issues)：把“用哪个麦克风”和“何时收音”分开，用下拉而非要求用户记设备序号。
- [Discord Push-to-Talk 说明](https://support.discord.com/hc/en-us/articles/211376518-Voice-Input-Modes-101-Push-to-Talk-Voice-Activated)：设置围绕可理解的说话动作，而不是后台进程术语。
- [Wispr Flow 麦克风选择](https://docs.wisprflow.ai/articles/8884408990-connect-and-set-up-external-audio-devices)：提供系统默认与直接设备选择入口。
- [Wispr Flow 无声/不可用麦克风排查](https://docs.wisprflow.ai/articles/4351452717-troubleshooting-mic-issues)：错误要指出可执行的下一步，而不是泛化“未核验”。

鱼应没有照搬自动切换设备或自动恢复录音；设备变化、归属变化与失败写入仍遵守现有安全边界。

## 验证与限制

本地可重复检查包括 Node 核心/桥接、Python、真实发布 rc.1 服务 fixture、生产 UI 装配，以及自动读取/取消/切换来源的回归。浏览器脚本覆盖候选选择、接管取消、窄窗/深浅色、键盘、拖拽、重复操作与首次配置。

当前本地结果：343 项 Node、82 项 Python、8 项已发布 rc.1 服务用例通过；UI 用例扩充至 95 项。最终提交会触发 Windows 离线与 Chromium fixture CI；应以该提交的实际结果为准。历史版本通过不冒充本版通过。

未验证：用户原 Windows 桌面真实设备、实际 ASR/TTS 声音、在线服务时延、模型质量、GPU 和系统权限。所有无密钥 fixture 的通过均不等于“真实开麦 → 说一句 → 听到回答”已在用户机器上验收。不关闭 issue #7，不把上述未实测项写成完成。
