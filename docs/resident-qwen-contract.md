# Qwen 常驻合成与流式边界

## 两种不同的等待

对话模型开始回复很快，并不代表朗读已开始。逐句运行 `llama-tts` 会重复加载模型，且要生成完整 WAV 后才能播放。常驻 `llama-server` 可以省去后续句子的重复模型加载；它仍然需要完成这一句的合成。真正的边生成边播放是另一条路径，不能用“常驻”代替“流式”的验收。

## 固定、独占的本地服务

只使用已安装、已校验的 b12110 CPU/Vulkan 归档。补充清单记录相同归档中服务器及其实现库的字节数和 SHA-256，不改写旧安装清单、安装任务的 manifestHash 或用户计算设置。每次实际朗读仍校验资产；不下载新模型、运行组件、驱动或依赖。旧安装缺少可复用归档时，保留已校验 CLI 路径。

只有已确认退出的 GPU 启动失败，且尚未发送 `/tts`、尚未触及播放器时，允许沿用同一参考音色快照走一次 CPU CLI 兜底。已发送请求、取消、文件校验失败或终止不确定都不重试；相同失败身份记住至相关资产或配置改变。

服务器由插件独占启动，只绑定数字地址 `127.0.0.1`，操作系统分配空闲端口，并关闭 Web UI。随机 API 密钥只经子进程环境与本机请求头传递，不放命令行或用户状态。不会接管已有端口，不会连接用户自行配置的任意服务，也不会结束非本插件创建的进程。

模型、运行组件、参考音色或配置身份变动会停止旧服务后重新创建。快模式保持到显式关闭；其他模式在空闲 60 秒后释放。检查状态不启动或续租服务。关闭麦克风、停止朗读、撤销授权、关闭插件和异常停止必须等待所属播放与推理进程确认关闭。无法确认关闭时阻止新朗读，保留可能仍被占用的临时文件。

## 完整 WAV 路径

生产候选使用 `/tts` 的 `stream:false`、`response_format:wav`，先检查 HTTP 状态和完整音频，再交给原有播放器。固定采样参数保持 CLI 基线：seed 42、top-k 40、top-p 0.95、repeat penalty 1.0、n_predict 2048；temperature 0.8 在启动参数中设置，上游不读取 JSON temperature。

合法 WAV 与成功播放不代表服务端明确报告了自然结束。b12110 的响应没有 finish_reason，不能由此区分自然 EOS 和生成上限。不要把文件有效性写成未经证明的语义完整性，也不报告声学首音延迟。GPU 状态必须有已选真实设备和所属推理进程的正数卸载层数，HTTP 200、安装 Vulkan 或请求 GPU 均不足以证明 GPU 推理。

## 增量 PCM 仍为实验接口

固定源码证实 `/tts` 在解码循环中输出单声道 little-endian float32 PCM，响应头为 `audio/pcm;rate=...;encoding=float;bits=32`。它不是整段 WAV 假装分块。然而，首块发送后的推理错误与正常 HTTP EOF 使用同一个返回值，响应没有可靠的最终成功标记。通用 resumable stream 只能转发这些字节，不能补回已经丢失的错误信息。

因此 PCM 保持显式 `experimental-pcm` 的内部接口，不是用户默认朗读路线。结果仅为 `transport-eof-unconfirmed`。播放器使用有界背压和显式端点，首次提交音频即认为可能已播放。发生错误、断流、取消或停止不确定时不重播，不自动切设备、CPU 或在线语音。生产启用还需要可靠的终态协议和真实 Windows 音频连续性/取消验收。

## 验证如何解读

- 单元测试与本地 HTTP 夹具覆盖鉴权、分块重组、PCM 有限值、边界长度、取消、错误与所有权。
- 固定发布归档哈希和 `--version` 验证证明使用了预定程序，不等同于真实模型推理。
- Windows 无设备测试编译原生 helper，并在打开设备前验证错误头拒绝。它不验证真实扬声器或虚拟音频路由。
- 真实冷/暖 CPU 测量、GPU 参与证据、声学首音、播音连续性和自然结束必须分别记录，不把其中一个当成另一个。

## 本轮真实 CPU 观测

固定 b12110、Qwen3-TTS 1.7B Base Q4_K_M 与 Q8_0 mmproj，两模型大小和 SHA-256 均与清单一致。云 Linux、4 线程、无参考音色、无物理播放。以下只是单次工程检查，不是性能承诺或音质验收。

- 原始协议：服务器启动约 4.78 秒；同 PID 首次短句请求 9.25 秒、后续 5.37 秒，二者 WAV 字节哈希一致，24 kHz/mono/16-bit/1.44 秒。启动时间不包含在请求时间里。无密钥请求被 401 拒绝。
- 最终模块联通：真实提取校验的服务器、直接本机 HTTP、完整 WAV 校验和仅验证不播放的回调，两次短句同 PID 且只启动一次；冷调用 17.07 秒、暖调用 5.74 秒。该检查注入已验证模型的托管描述符，模型哈希在启动器再次校验，未以真实安装器逐句哈希耗时作为性能测量。
- 长句 PCM：输出 9.84 秒音频，首次消费约 10.84 秒、结束 18.34 秒，两批模型音频分别约 5.76 秒和 4.08 秒。消费侧的 4096 字节小帧是本地拆分，不当作模型分段数量。短句 PCM 首块约 5.15 秒，几乎与结束同时到达，不能宣称短句流式提速。
- 所属服务器均确认关闭，临时提取目录删除。没有 GPU 推理、真实 Windows 播放、声学首音或自然 EOS 的验收结论。PCM 仍未默认启用。
